# Spot arbitrage bot: MEXC ↔ NonKYC

> **Экспериментальный проект.** Этот робот предназначен только для исследовательских и учебных целей. Использование реальных средств может привести к полной или частичной потере капитала. Запускайте его только после самостоятельной проверки кода, API, комиссий, лимитов и законодательства, на свой риск и только с суммой, которую готовы потерять.

Проект не является финансовой рекомендацией, инвестиционной услугой или гарантией прибыли. Автор не несёт ответственности за убытки, ошибки API, задержки сети, проскальзывание, частичное исполнение, блокировку аккаунта или изменение правил бирж.

Торговый сервис для хеджированного спотового арбитража между MEXC и NonKYC. Он использует заранее размещённые на обеих биржах `quote` и `base` балансы, рассчитывает исполнимую чистую маржу и при явном включении live-режима отправляет две лимитные заявки параллельно, без перевода средств в момент сделки.

> Арбитраж не гарантирует прибыль. Спред может исчезнуть до исполнения, а перевод между биржами может быть задержан, ограничен сетью или отменён. Сначала проверьте правила региона, аккаунтов и API обеих бирж.

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
python -m arbitrage_bot
```

Связку бирж можно выбрать аргументом:

```bash
python -m arbitrage_bot --pair mexc-xeggex
```

Доступны `mexc-nonkyc` (по умолчанию), `mexc-xeggex` и `nonkyc-xeggex`. Аргумент `--pair` имеет приоритет над `ARB_PAIR` в `.env`.

Поддерживаемые биржи (регистр не важен, любая комбинация двух разных): `mexc`, `nonkyc`, `xeggex`, `xt`, `lbank`, `bingx`, `htx`, `gate`, `bitrue`, `whitebit`. Например `--pair mexc-xt` или `--pair whitebit-nonkyc`. NonKYC и XeggeX работают через собственные адаптеры, остальные — через ccxt. Комиссия taker по умолчанию берётся из встроенной консервативной оценки и переопределяется переменной `<ID>_FEE_BPS` (например `BITRUE_FEE_BPS=30`); API-ключи для live задаются в том же шаблоне `<ID>_API_KEY` / `<ID>_SECRET`.

Для XeggeX:

```bash
python -m arbitrage_bot --pair mexc-xeggex
```

Параметры XeggeX берутся из `XEGGEX_API_KEY`, `XEGGEX_SECRET` и `XEGGEX_FEE_BPS`. Если рынок активен, но его стакан пуст, сигнал не формируется — это нормальная защита от неисполняемой сделки. Последняя цена или ticker не используются вместо стакана, потому что не показывают доступный объём.

Остановить демо или робота можно клавишами `Ctrl+C`; программа завершится штатно без traceback и закроет сетевые сессии.

## Веб-интерфейс (мониторинг и расчёт позиций)

Вместо консоли бот можно управлять из браузера — интерфейс работает только в dry-run и никогда не отправляет ордера:

```bash
python -m arbitrage_bot.web
```

Откроется `http://127.0.0.1:8788` (порт и хост настраиваются `WEB_PORT`/`WEB_HOST` или аргументами `--port`/`--host`; `--no-browser` отключает автозапуск браузера). Возможности:

- **Живой сканер спредов** — таблица по всем общим парам выбранной связки: оба направления, net edge в bps, оценка прибыли, VWAP-цены, объём и возраст стаканов. Строки появляются по мере опроса, фильтр по символу, подсветка сигналов выше `MIN_NET_EDGE_BPS`.
- **Калькулятор позиции** — расчёт прибыли от суммы входа по свежим стаканам для любого символа: исполнимый объём по встречной глубине, VWAP покупки/продажи, затраты и выручка с комиссиями, чистая прибыль, net edge и доходность в процентах от фактически задействованной суммы. Клик по строке сигнала подставляет символ и считает сразу; пресеты сумм `10/25/50/100/250/500` USDT; при включённом «авто» калькулятор сам подтягивает лучший сигнал сканера (не чаще раза в 10 секунд, отключается галочкой).
- Переключение любых связок из списка поддерживаемых бирж (два выпадающих списка в интерфейсе), настройка интервала опроса и лимита пар.

API интерфейса: `GET /api/session`, `POST /api/session`, `POST /api/scan/start`, `POST /api/scan/stop`, `GET /api/snapshot`, `POST /api/calc` — те же данные можно забирать скриптами.

### Скрипты мониторинга (scripts/)

- **`scripts/monitor_spreads.py`** — длительный сбор статистики спредов по одной связке: поднимает сканер без браузера, опрашивает снапшоты и копит по каждой паре×направлению min/avg/max edge, долю сигнальных опросов и объём. Итог сохраняется в `spread_monitor_results.json` (в `.gitignore`). Запуск из корня репозитория:
  ```bash
  python scripts/monitor_spreads.py --pair mexc-nonkyc --port 8791 --min-cycles 10 --max-seconds 420
  ```
- **`scripts/depth_probe.py`** — проверка кандидатов по реальной глубине: сколько можно исполнить на $25/$50/$100/$200 с учётом проходки по 50 уровням и комиссий. Отличает живые спреды от «фантомов» последнего уровня (список кандидатов задаётся в шапке файла):
  ```bash
  python scripts/depth_probe.py
  ```

Оба скрипта только читают рыночные данные и не отправляют ордера.

Переменная `LIVE_TRADING=false` обязательна для первого запуска. Для реальной торговли сначала используйте отдельные аккаунты, API-ключи только с разрешением Spot Trade, whitelist IP и без права вывода. Автоматические withdrawals намеренно не реализованы: адрес, сеть, memo/tag и лимиты нужно подтверждать отдельно.

## Последние изменения

- Расширен список бирж: добавлены XT, LBank, BingX, HTX, Gate, Bitrue, WhiteBit (через ccxt); единый реестр бирж, любые связки из 10 площадок (например `mexc-xt`, `whitebit-nonkyc`), комиссии через `<ID>_FEE_BPS`, динамический выбор связки в веб-интерфейсе.
- Добавлены скрипты мониторинга спредов (`scripts/monitor_spreads.py`, `scripts/depth_probe.py`): длительный сбор статистики по связкам и проверка кандидатов по глубине стаканов с учётом комиссий; оба работают в dry-run и только читают данные.
- Добавлен веб-интерфейс (`python -m arbitrage_bot.web`): живой сканер спредов и калькулятор позиций по реальным стаканам в браузере, без отправки ордеров и без новых зависимостей.
- Исправлен крах на старте в dry-run без API-ключей MEXC: если комиссию получить нельзя, используется консервативная оценка `5 bps` (live-режим по-прежнему требует реальные данные и останавливается).
- Комиссия MEXC запрашивается один раз и кэшируется: ставка аккаунт-уровня и одинакова для всех пар, поэтому `SYMBOLS=ALL` больше не порождает ~100 последовательных авторизованных запросов при старте.
- Расчёт `net_edge_bps` для NonKYC и XeggeX использует цену защитного уровня `PROTECTIVE_PRICE_LEVEL` (по умолчанию 3), а не только лучшую котировку.
- Для MEXC стоимость и выручка оцениваются по VWAP доступной глубины; лимитная IOC-цена выставляется агрессивно до последнего задействованного уровня.
- Объём сделки ограничивается меньшим значением из `MAX_NOTIONAL_QUOTE`, траншевого и общего лимитов, доступной ликвидности первого уровня и свободных балансов. Поэтому лимит `100 USDT` не означает, что каждая сделка будет ровно на `100 USDT`.
- При `SYMBOLS=ALL` общий лимит не умножается на количество пар: `MAX_TOTAL_SESSION_NOTIONAL=100` ограничивает суммарный номинал всех активных серий в процессе.
- После успешной сделки следующий транш по той же паре возможен только после cooldown при сохранении свежего спреда. Серия ограничена `MAX_SESSION_NOTIONAL` и сбрасывается, если спред опустился ниже `REARM_EDGE_BPS`.
- Для NonKYC и XeggeX сохраняются агрессивные лимитные заявки без фиктивного IOC; зависшие заявки отменяются, а неполное исполнение хеджируется отдельно.

## Настройка

- `SYMBOLS` — список пар или `ALL`. При `ALL` бот автоматически выбирает все общие активные spot-пары с `QUOTE_CURRENCY` на выбранной связке; `MAX_SYMBOLS=0` означает без ограничения. Пустые стаканы и пары без достаточной глубины пропускаются.
- `QUOTE_CURRENCY` — котируемая валюта для режима `ALL`, по умолчанию `USDT`.
- `MAX_SYMBOLS` — необязательное ограничение количества автоматически найденных общих пар.
- `MIN_NET_EDGE_BPS` — минимальная чистая маржа в basis points после комиссий и запаса проскальзывания.
- `MAX_NET_EDGE_BPS` — верхний safety cap для аномальных котировок; по умолчанию `5000` bps (`50%`). Выбросы выше лимита только логируются и не допускаются к сигналу или live-исполнению.
- `MAX_NOTIONAL_QUOTE` — максимальный номинал одной стороны; фактический размер дополнительно ограничивается свободными балансами на обеих биржах.
- `MAX_SLICE_NOTIONAL` — максимум номинала одного транша при поэтапном исполнении; по умолчанию `10 USDT`.
- `MAX_SESSION_NOTIONAL` — максимум суммарного номинала траншей по одной паре, пока спред не сбросился; по умолчанию `100 USDT`.
- `MAX_TOTAL_SESSION_NOTIONAL` — общий максимум суммарного номинала траншей по всем парам в процессе; по умолчанию `100 USDT`. При `SYMBOLS=ALL` лимит не умножается на количество пар.
- `POLL_INTERVAL_SECONDS` — частота обновления в dry-run; не уменьшайте без проверки rate limits.
- `MEXC_FEE_BPS` — необязательный fallback в bps. При ключах и `AUTO_FETCH_MEXC_FEE=true` бот получает фактическую MEXC `taker`-ставку через CCXT: ставка аккаунт-уровня, поэтому выполняется один запрос, результат кэшируется для всех пар. Если данные недоступны — в dry-run используется консервативная оценка `5 bps`, в live запуск останавливается.
- `NONKYC_FEE_BPS` — ручная фактическая ставка NonKYC в bps: официальный API NonKYC не предоставляет endpoint trading fee.
- `XEGGEX_FEE_BPS` — ручная фактическая `taker`-ставка XeggeX в bps.
- `ARB_PAIR` — связка по умолчанию, например `mexc-xeggex`.
- `SLIPPAGE_BUFFER_BPS` — отдельный запас на проскальзывание, это не комиссия биржи.
- `TRADE_COOLDOWN_SECONDS` — пауза после завершённой сделки перед новым входом по той же паре.
- `REARM_EDGE_BPS` — после сделки спред должен опуститься ниже этого значения, чтобы пара снова стала доступной для входа.
- `PROTECTIVE_PRICE_LEVEL` — уровень консервативной цены для бирж без нативного IOC; объём таких заявок ограничивается первым уровнем стакана. Маржа считается по этому же уровню, а не по best bid/ask.

MEXC интегрирован через CCXT. Поскольку CCXT `4.5.78` не содержит `nonkyc` и `xeggex`, в проект добавлены локальные CCXT-shaped адаптеры [`NonKycExchange`](src/arbitrage_bot/nonkyc.py) и [`XeggexExchange`](src/arbitrage_bot/xeggex.py). Они реализуют public markets/order book и private balances/order lifecycle по официальным API бирж. XeggeX использует Basic Auth, NonKYC — HMAC-заголовки.

В dry-run лог также показывает направление, чистую маржу и оценку результата, если спред найден, но не проходит порог. Отрицательная маржа означает убыточную сделку после комиссий и буфера; снижение `MIN_NET_EDGE_BPS` не сделает её прибыльной.

Пример результата dry-run:

```text
2026-09-08 22:47:49,296 INFO CHECK LTCUSDT buy=mexc sell=nonkyc net_edge=170.25 bps profit≈1.8024971066966623640051632
2026-09-08 22:47:49,297 INFO CHECK LTCUSDT buy=nonkyc sell=mexc net_edge=-875.85 bps profit≈-8.65853887338679723113287183
2026-09-08 22:47:49,297 INFO 🚨 ARBITRAGE LTCUSDT buy=mexc sell=nonkyc qty=1.844010990226811727825926609 edge=170.25 bps profit≈1.8024971066966623640051632
2026-09-08 22:47:49,677 INFO CHECK BCHUSDT buy=mexc sell=nonkyc net_edge=-76.50 bps profit≈-0.66500030644054580896686159
2026-09-08 22:47:49,677 INFO CHECK BCHUSDT buy=nonkyc sell=mexc net_edge=-742.32 bps profit≈-7.32317115467439333574791741
```

В этом примере бот проверил оба направления по каждой паре и выбрал LTC: покупка на MEXC, продажа на NonKYC, чистая маржа `170.25 bps` (`1.7025%`) и расчётная прибыль около `1.80 USDT` для указанного объёма. Это только сигнал: фактический результат зависит от доступного баланса, глубины стакана, исполнения обеих ног и проскальзывания.

Важно правильно читать экстремальные сигналы. Например, `PEPE/USDT` с `501.63 bps` означает расчётную маржу около `5.02%`, но не гарантированную прибыль. Сигнал вроде `TROLL/USDT` с сотнями тысяч `bps` считается аномальным: он может быть вызван разными ценами листинга, микроликвидностью, stale-котировкой или невозможностью реально исполнить весь объём. Такие значения бот отклоняет через `MAX_NET_EDGE_BPS` и не отправляет в live-исполнение.

Объём рассчитывается по фактическому пересечению доступных уровней покупки и продажи. Поэтому большая разница цен сама по себе недостаточна: на обеих площадках должны быть встречные заявки, допустимые market limits, свободные балансы и подтверждаемое исполнение.

При найденном исполнимом арбитраже строка выводится зелёным цветом с маркером `🚨 ARBITRAGE`. Если вывод перенаправлен в файл, ANSI-цвета отключаются; для принудительного включения используйте `FORCE_COLOR=true`.

## Режимы и ограничения

1. `dry-run` — только котировки и сигналы.
2. `LIVE_TRADING=true` требует ключи обеих бирж и доступный адаптер. Перед сделкой исполнитель обновляет стаканы, проверяет свободный `quote` для покупки и `base` для продажи, затем параллельно выставляет обе ноги и сверяет fills. Для MEXC стратегия оценивает VWAP, а нативный `timeInForce=IOC` получает агрессивную лимитную цену до последнего задействованного уровня. NonKYC и XeggeX используют цену до `PROTECTIVE_PRICE_LEVEL` и объём не выше первого уровня, после чего зависшая заявка отменяется. Это снижает race condition, но не обеспечивает атомарность или гарантированное исполнение за фиксированное число миллисекунд.
3. Хеджированный арбитраж не оставляет обычную открытую позицию: выход происходит после исполнения двух ног и residual hedge. Следующий транш по той же паре возможен только после cooldown при сохранении свежего спреда. Серия ограничена `MAX_SESSION_NOTIONAL` и сбрасывается, если спред опустился ниже `REARM_EDGE_BPS`. Счётчик серии хранится в памяти и после перезапуска начинается заново.
4. Переводы между биржами не автоматизируются. Для арбитража с уже размещённой ликвидностью на обеих биржах перевод обычно не находится на критическом пути каждой сделки.
5. Бот не пытается обходить rate limits, антибот-защиту, географические ограничения, KYC/AML или условия обслуживания.

`MAX_TOTAL_SESSION_NOTIONAL` ограничивает торговый оборот, а не отменяет требование к капиталу: для хеджированной сделки нужен `quote`-резерв на бирже покупки и запас `base`-актива на бирже продажи. Их объём и стоимость необходимо рассчитывать отдельно перед live-запуском.

## Проверки перед live

- проверить доступность API и статус рынков вручную;
- сверить symbol, точность количества/цены, min-notional, комиссии и разрешённые сети;
- держать одинаковый активный инвентарь на обеих биржах;
- настроить внешний kill-switch, лимит дневного убытка и хранение состояния/reconciliation в устойчивой БД;
- получить юридическое/налоговое заключение для своей юрисдикции.

Источники: официальная документация MEXC Spot API V3 и официальный GitHub-клиент NonKYC.
