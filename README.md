Запускайте его только после самостоятельной проверки кода, API, комиссий, лимитов и законодательства, на свой риск и только с суммой, которую готовы потерять.

Проект не является финансовой рекомендацией, инвестиционной услугой или гарантией прибыли. Автор не несёт ответственности за убытки, ошибки API, задержки сети, проскальзывание, частичное исполнение, блокировку аккаунта или изменение правил бирж.

Торговый сервис для хеджированного спотового арбитража между MEXC и NonKYC. Он использует заранее размещённые на обеих биржах `quote` и `base` балансы, рассчитывает исполнимую чистую маржу и при явном включении live-режима отправляет две лимитные заявки параллельно, без перевода средств в момент сделки.

> Арбитраж не гарантирует прибыль. Спред может исчезнуть до исполнения, а перевод между биржами может быть задержан, ограничен сетью или отменён. Сначала проверьте правила региона, аккаунтов и API обеих бирж.

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
python -m arbitrage_bot
```

Переменная `LIVE_TRADING=false` обязательна для первого запуска. Для реальной торговли сначала используйте отдельные аккаунты, API-ключи только с разрешением Spot Trade, whitelist IP и без права вывода. Автоматические withdrawals намеренно не реализованы: адрес, сеть, memo/tag и лимиты нужно подтверждать отдельно.

## Настройка

- `SYMBOLS` — пары в формате `BTCUSDT,ETHUSDT,XRPUSDT,SOLUSDT,DOGEUSDT`. После загрузки рынков бот автоматически оставляет только активные пары, присутствующие одновременно на MEXC и NonKYC.
- `MIN_NET_EDGE_BPS` — минимальная чистая маржа в basis points после комиссий и запаса проскальзывания.
- `MAX_NOTIONAL_QUOTE` — максимальный номинал одной стороны; фактический размер дополнительно ограничивается свободными балансами на обеих биржах.
- `POLL_INTERVAL_SECONDS` — частота обновления в dry-run; не уменьшайте без проверки rate limits.
- `MEXC_FEE_BPS` — необязательный fallback в bps. При ключах и `AUTO_FETCH_MEXC_FEE=true` бот получает фактическую MEXC `taker`-ставку через CCXT для каждой пары; в live при ошибке lookup запуск останавливается.
- `NONKYC_FEE_BPS` — ручная фактическая ставка NonKYC в bps: официальный API NonKYC не предоставляет endpoint trading fee.
- `SLIPPAGE_BUFFER_BPS` — отдельный запас на проскальзывание, это не комиссия биржи.
- `TRADE_COOLDOWN_SECONDS` — пауза после завершённой сделки перед новым входом по той же паре.
- `REARM_EDGE_BPS` — после сделки спред должен опуститься ниже этого значения, чтобы пара снова стала доступной для входа.

MEXC интегрирован через CCXT. Поскольку CCXT `4.5.78` не содержит `nonkyc`, в проект добавлен локальный CCXT-shaped адаптер [`NonKycExchange`](src/arbitrage_bot/nonkyc.py), реализованный по официальному Python-клиенту NonKYC: public markets/order book, HMAC-аутентификация, balances, create/fetch/cancel order. Публичная загрузка рынков и стакана `BTC/USDT` проверена против API NonKYC.

В dry-run лог также показывает направление, чистую маржу и оценку результата, если спред найден, но не проходит порог. Отрицательная маржа означает убыточную сделку после комиссий и буфера; снижение `MIN_NET_EDGE_BPS` не сделает её прибыльной.

При найденном исполнимом арбитраже строка выводится зелёным цветом с маркером `🚨 ARBITRAGE`. Если вывод перенаправлен в файл, ANSI-цвета отключаются; для принудительного включения используйте `FORCE_COLOR=true`.

## Режимы и ограничения

1. `dry-run` — только котировки и сигналы.
2. `LIVE_TRADING=true` требует ключи обеих бирж и доступный адаптер. Перед сделкой исполнитель проверяет свободный `quote` для покупки и `base` для продажи, затем параллельно выставляет обе ноги, сверяет фактические fills и хеджирует остаток на бирже, где возник дисбаланс. У REST API NonKYC нет нативного IOC: адаптер создаёт limit order и сразу отменяет его, как в официальном примере NonKYC. Это не исключает частичного исполнения между запросами.
3. Хеджированный арбитраж не оставляет обычную открытую позицию: выход происходит после исполнения двух ног и residual hedge. После успешного закрытия `TradeGate` блокирует повторный вход по паре на `TRADE_COOLDOWN_SECONDS` и требует сброса спреда ниже `REARM_EDGE_BPS`.
4. Переводы между биржами не автоматизируются. Для арбитража с уже размещённой ликвидностью на обеих биржах перевод обычно не находится на критическом пути каждой сделки.
5. Бот не пытается обходить rate limits, антибот-защиту, географические ограничения, KYC/AML или условия обслуживания.

## Проверки перед live

- проверить доступность API и статус рынков вручную;
- сверить symbol, точность количества/цены, min-notional, комиссии и разрешённые сети;
- держать одинаковый активный инвентарь на обеих биржах;
- настроить внешний kill-switch, лимит дневного убытка и хранение состояния/reconciliation в устойчивой БД;
- получить юридическое/налоговое заключение для своей юрисдикции.

Источники: официальная документация MEXC Spot API V3 и официальный GitHub-клиент NonKYC.
